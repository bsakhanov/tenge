# Цифровой тенге в Казахстане: доклад-исследование

Рабочий репозиторий регулярного исследования проекта «цифровой тенге» (РК): доклад, реестры фактов, методология, список наблюдения и сборка. Цель: каждые полгода обновлять доклад и выпускать новые, более актуальные редакции, не теряя связи с предыдущими.

**Текущая редакция:** 1.0, срез данных 31 октября 2026 года. Файлы: `editions/1.0/` и страница релиза `v1.0`.

## Что внутри

```
edition.yml               паспорт редакции (номер, дата, срез, вид выпуска)
CHANGELOG.md              что менялось от редакции к редакции
report/src/               исходники доклада в Markdown: front, vol1–vol6, appendix
registry/                 реестры как данные: facts.csv, discrepancies.csv, gaps.csv
watch/                    список наблюдения, поисковые запросы, временной ряд показателей
sources/                  манифест источников (файлы в git не кладутся)
methodology/              протокол обновления, иерархия источников, типографика, уроки, бэклог
scripts/                  сборка, проверки, линтер, манифест, извлечение текста
editions/<X.Y>/           выпущенные docx и PDF, снимок реестров, SHA256SUMS
.github/                  шаблоны задач и автоматизация
```

## Быстрый старт

Требуется: Python 3.10+, pandoc, LibreOffice (`soffice`), poppler (`pdfinfo`, `pdftotext`), шрифты Times New Roman и Arial (либо метрически совместимые Liberation).

```bash
pip install -r requirements.txt
make check     # целостность кодов Ф-/Р-/М-/R-, ссылки, счётчики
make lint      # типографика и язык (предупреждения)
make build     # docx + PDF в dist/ с оглавлением и проверкой вёрстки
make snapshot  # зафиксировать выпуск в editions/<X.Y>/
```

Правки вносятся только в `report/src/*.md` и `registry/*.csv`. Таблицы приложений А–В и счётчики в титуле и резюме собираются автоматически; руками их править не нужно.

## Как выпускать новую редакцию

Коротко: открыть задачу «Цикл обновления» → собрать новое по списку наблюдения → пройти реестр и пометить устаревшее (`superseded`) → проверить новые тезисы по протоколу → править тома → языковой прогон → `make build` → обновить `edition.yml` и `CHANGELOG.md` → `make snapshot` → тег `vX.Y`. Подробно: `methodology/update-protocol.md`.

Ритм: весна (срез 30 апреля) — X.1; осень (срез 31 октября) — X.0; внеочередной выпуск — при триггерах из протокола.

## Принципы

1. Факты не удаляются; устаревший факт заменяется ссылкой на новый.
2. Каждое число имеет источник и дату среза; непроверенное помечается и выносится в реестр расхождений или белых пятен.
3. Оценки автора подписаны как оценки.
4. Внешние материалы (черновики, статьи, записки партнёров) проверяются по первоисточнику; вердикт фиксируется.
5. Данные оператора принимаются как его заявления, а не как независимый аудит.
